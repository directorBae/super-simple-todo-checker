# 데스크톱 집중 공간

`desktop`의 Electron 앱에 구현되어 있습니다. 기존 Android/iOS 설치 파일과 `artifacts`의 배포본은 이 변경을 포함하지 않습니다.

## 실행

브라우저에서 사용하려면 `desktop` 폴더에서 `npm run web`을 실행하고 <http://127.0.0.1:5173>에 접속합니다. 웹 서비스가 현재 소스의 동기화 서버도 함께 실행하므로 8787 포트는 비어 있어야 합니다. 데이터와 도구 연결은 `server/data`의 SQLite를 사용하며, 웹의 테마·펫 설정은 같은 폴더의 `web-settings.json`에 저장합니다. 서버 `.env`의 API 설정을 그대로 사용합니다. 브라우저에서는 Windows 자동 실행·트레이 알림을 제공하지 않습니다.

저장소 루트에서 터미널 두 개로 실행합니다.

```powershell
cd server
npm start
```

```powershell
cd desktop
npm start
```

처음 설치한 환경에서는 각 폴더에서 `npm ci`를 먼저 실행합니다. 첫 실행 화면에서 도구를 연결하거나 ‘지금은 건너뛰기’를 누르면 집중 공간이 열립니다.

현재 IDE에 열린 `artifacts/demo-2026-09-14-v1.1.1/.../start-server.cmd`는 예전 배포 서버를 실행합니다. 도구 연결과 Supabase 동기화에는 현재 저장소의 `server/index.js`가 필요합니다. 기존 서버를 쓰고 있다면 그 서버를 종료한 뒤 같은 데이터·설정을 유지하며 업데이트해야 합니다. 실행 중인 서버를 교체하거나 기존 데이터 폴더를 이동하는 작업은 이번 변경에 포함하지 않았습니다.

## 화면과 방

- 화면은 옆으로 붙은 세 개의 방입니다: **팀 · 버킷**(왼쪽) ← **메인**(할 일) → **시계**(오른쪽).
- PC: Ctrl+← / Ctrl+→ 로 한 칸씩 옮겨 갑니다. Esc는 메인으로 돌아갑니다. 양쪽 끝의 작은 `⠿` 손잡이를 안쪽으로 당기거나 클릭해도 열립니다. 입력칸에 커서가 있을 때는 단축키가 동작하지 않습니다.
- 휴대폰: 화면 왼쪽 끝에서 오른쪽으로 밀면 팀 · 버킷, 오른쪽 끝에서 왼쪽으로 밀면 시계가 열립니다. 가운데 쪽으로 다시 밀면 메인으로 돌아옵니다.
- 옆 방은 휴대폰 상태바를 끌어내리듯 창 전체를 덮는 유리 시트입니다. 메인 화면은 그 아래에 흐리게 남습니다.
- 팀 · 버킷 방은 PC에서는 왼쪽 절반이 팀, 오른쪽 절반이 버킷입니다. 휴대폰에서는 위쪽 ‘팀 | 버킷’ 전환으로 나뉩니다.
- 상단에는 로고, 알림(차임벨, 안 읽은 알림 수 표시), 메뉴만 있습니다. 메뉴에는 ‘음악’과 ‘설정’만 있습니다. 휴대폰 앱에는 알림 기록이 없어 차임벨이 없습니다.
- 월 보기 캘린더 오른쪽에 내 팀 목록과 팀별 남은 할 일 수가 표시됩니다. ‘관리’를 누르면 팀 · 버킷 방이 열립니다.
- 일별 페이지는 입력 상자 없이 글자만 보입니다. 마우스를 올리거나(휴대폰은 입력 중) 고칠 때만 그 줄에 유리가 생깁니다. 오늘의 요일과 날짜만 반짝이며 빛납니다.

## 시계와 시간 배정

- 원형 시계는 시트를 꽉 채우는 유리 원판이며, 시각과 날짜는 바늘 아래에 반투명 유리 글자로 은은하게 비칩니다.
- PC에서는 Ctrl+우클릭으로도 시계를 엽니다. 할 일 제목을 약 0.45초 누른 뒤 오른쪽으로 끌거나, 할 일 옆 `⠿`를 오른쪽 끝으로 끌면 시계가 나타납니다. 시계 위에 놓으면 15분 단위로 시작 시간을 배정합니다.
- `⠿`를 클릭하면 그 할 일이 선택된 채로 시계가 열리고, 시계를 누른 위치의 시간으로 배정됩니다. 배정 직후 아래 알림에서 되돌릴 수 있습니다. 새 시작 시간과 충돌할 수 있는 기존 종료 시간은 해제합니다.

## 펫

- 펫은 24×24 도트 프레임으로 그립니다. 펫은 세 방 중 한 곳에 있고, 방의 경계를 걸어서 오갑니다. 주로 지금 보고 있는 방에서 놀고 가끔 옆방으로 건너갑니다. 쉴 때는 시계 방의 오른쪽 끝 너머로 들어갑니다.
- 메인에 있던 펫은 옆 방 시트를 열어도 메인 화면과 함께 시트 아래에 흐리게 남습니다. 옆 방에 있는 펫은 그 방을 볼 때만 보입니다.
- 왼쪽 아래 발바닥 버튼으로 부르면 실제 있던 위치에서 점프한 뒤 보고 있는 방으로 달려옵니다. 끌어서 옮길 때는 보고 있는 방 안에서만 움직입니다. PC에서 펫을 우클릭하거나 휴대폰의 부르기 버튼을 길게 누르면 쉬러 갑니다. 할 일을 완료해도 반응합니다.
- 시스템의 동작 줄이기 설정에서는 자율 이동과 점프 효과를 줄입니다. 펫 꾸미기 설정은 없앴고, 펫은 기본 모습으로 다닙니다.

## 음악과 게임

음악은 메뉴 → ‘음악’에서 YouTube 영상이나 재생목록 링크를 붙여 넣어 목록을 만듭니다(youtu.be, watch, shorts, 재생목록, music.youtube.com 링크). 공식 YouTube 플레이어로 재생하며, 곡이 끝나면 목록의 다음 항목을 자동으로 재생합니다. 처음 재생할 때 영상 제목을 목록에 저장합니다. 음악 창을 닫아도 계속 재생됩니다. 올린 사람이 다른 앱에서의 재생을 막아 둔 영상은 재생할 수 없어 안내 후 다음 항목으로 넘어갑니다.

- 자동 재생: PC 앱은 첫 곡부터 클릭 없이 재생되도록 설정했습니다. 웹 브라우저는 정책상 첫 재생에 한 번 클릭(재생 버튼)이 필요하고, 그 뒤 다음 곡은 자동으로 이어집니다. 휴대폰은 앱이 화면에 있는 동안 재생되며, 앱을 백그라운드로 보내면 iOS·Android가 재생을 멈춥니다.
- 목록은 기기별 설정에 저장되며 동기화하지 않습니다.

게임은 인터넷이 끊겼을 때 화면 구석에 나타나는 작은 공룡을 눌러 여는 이스터에그이며, 온라인 상태에서는 안내와 진입 버튼을 표시하지 않습니다. 다시 연결되면 게임 화면도 닫힙니다.

게임은 Space/방향키 또는 화면 버튼으로 조작합니다. P로 일시정지합니다. 게임을 시작하거나 계속할 때 게임 화면에 포커스가 갑니다. 다른 앱으로 이동하면 일시정지하고, 최고점은 게임 종료 시 저장됩니다.

| 점수 | 장르 |
|---|---|
| 0 | 공룡 달리기 |
| 1,000 | 마리오 스타일 플랫폼·코인 수집 |
| 2,000 | 공룡 달리기 |
| 3,000 | 갤러그 스타일 슈팅 |
| 4,000 | 공룡 달리기 |
| 5,000 | 팩맨 스타일 미로 |
| 6,000 | 공룡 달리기 |
| 7,000 | 리버스 마리오·쿠파 모드: 불꽃으로 다가오는 용사 막기 |

8,000점부터 같은 순서를 반복합니다. 그래픽은 Canvas로 그리는 앱 자체 도형입니다.

## 50자 제목

할 일 제목은 50자 이내로만 입력할 수 있습니다(PC·휴대폰 입력칸 모두). 도구 연결(Notion·Google·Apple)로 가져온 제목도 50자로 줄이고 원문은 메모에 남깁니다. 가져온 원본은 앱에서 그 할 일을 고치기 전까지 다시 쓰지 않습니다.

## 배경 화면과 월페이퍼

설정 → ‘배경 화면’에서 기본 사진 7장 중 고르거나 직접 사진을 올립니다. 올린 사진은 화면 크기로 줄여 이 기기에만 저장합니다. 기본 사진은 모두 Unsplash 무료 라이선스이며 출처는 [wallpaper-credits.md](wallpaper-credits.md)에 있습니다. 앱 전체는 이 사진 위에 유리(가장자리 굴절 + 블러) 재질로 그립니다.

같은 화면의 ‘월페이퍼 저장’은 시계와 펫을 독립 HTML 파일로 저장합니다. 브라우저에서 열거나 Windows의 Lively Wallpaper에 추가할 수 있습니다. 외부 자원 없이 실시간 날짜·시계를 표시하고 펫을 이동할 수 있습니다. [Lively Web Player 공식 안내](https://github.com/lively-community/lively/wiki/Web-Player).

## 설정

메뉴 → 설정은 ‘일반(알림·자동 실행) · 배경 화면 · 도구 연결 · 휴대폰 연결 · 정보’ 탭으로 나뉩니다. 휴대폰 앱은 ‘배경 화면 · 도구 연결 · PC 연결’입니다. 데이터는 Supabase로 동기화되며 화면에는 따로 표시하지 않습니다. 설정 방법은 [supabase.md](supabase.md).

```powershell
cd desktop

npm run test:ui
npm run test:sync
cd ../server
npm test
```

UI 검사는 실제 사용자 데이터와 분리된 `artifacts/focus-qa`에 스크린샷과 내보낸 월페이퍼를 저장합니다. UI 검사의 LLM 응답은 모의 응답입니다. 실제 API 확인은 별도로 수행해야 합니다.
