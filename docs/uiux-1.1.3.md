# 1.1.3 — Notion 담당자 필터

PC·iPhone·Android의 메모장 UI를 유지하면서 Notion 연결 팝업에 담당자 필터를 추가했습니다.

## 연결 순서

1. Notion 내부 연결에 콘텐츠 읽기·삽입·수정 권한과 **사용자 정보 읽기** 권한을 허용합니다. 이메일 읽기는 선택 사항입니다.
2. 가져올 DB를 해당 연결에 공유하고 사람 유형의 담당자 속성을 준비합니다.
3. 체커 → 도구 연결 → Notion → 연결 계정의 **위치 선택** → DB 선택.
4. **내가 담당자인 업무만 가져오기**를 켜고 담당자 속성을 선택합니다.
5. **담당자 목록 불러오기** → **내 Notion 계정**에서 본인을 선택합니다.
6. 팀과 데이터베이스 속성을 확인한 뒤 **저장하고 가져오기**를 누릅니다.

내부 연결 토큰은 봇을 인증하므로 본인 계정을 자동으로 추정하지 않습니다. DB마다 사용자 ID를 저장합니다. 새 DB 연결은 필터가 기본으로 켜져 있고, 기존 연결은 종전 설정을 유지하므로 위 절차로 필터를 켜야 합니다. 담당자 없이 전체 DB를 가져오려면 필터를 끌 수 있습니다.

Notion 사용자 목록에는 게스트가 포함되지 않습니다. 목록에 없는 게스트는 **사용자 ID로 입력**에서 Notion 사용자 UUID를 지정할 수 있습니다. 서버가 해당 사용자를 조회해 사람 계정인지 확인합니다. 이름이 같아도 ID로 구분합니다.

## 동기화 동작

- 선택한 사람이 공동 담당자 중 한 명인 업무도 포함합니다. 미배정·타인만 배정된 업무는 제외합니다.
- Notion에서 다른 사람에게 재배정하면 다음 가져오기에서 체커 목록에서 제외합니다. 로컬 원본 기록과 연결 ID는 서버에 보존하며 Notion 페이지는 삭제하지 않습니다.
- 다시 본인에게 배정되면 기존 체커 업무 ID로 복원합니다. 사용자가 직접 삭제한 업무는 기존 삭제 정책을 유지합니다.
- 여러 소스를 합친 업무는 다른 유효한 소스가 남아 있으면 계속 표시합니다.
- 새 업무를 이 Notion DB에 생성할 때는 선택한 사람을 담당자로 지정합니다. 기존 업무의 제목·날짜 수정은 다른 공동 담당자를 덮어쓰지 않습니다.
- 전송 직전에 담당자가 바뀌었는지도 확인합니다. 필터에서 제외된 원본에는 대기 중 수정·삭제를 전송하지 않습니다.
- 이미 생성했는지 불명확한 요청은 담당자 필터와 별개로 앱 ID를 조회하여 중복 생성을 방지합니다.

## 설치와 서버

1.1.3 PC 설치 파일과 Android APK는 기존 앱 위에 설치합니다. iPhone은 등록된 기기의 Safari에서 EAS 설치 페이지를 엽니다. 계정·서버 주소를 유지하려면 기존 앱을 먼저 삭제하지 마세요.

서버 주소는 기존 `http://192.168.150.151:8787`을 유지합니다. 서버의 데이터와 API 키를 다른 폴더로 옮길 필요가 없습니다. 로그인 비밀번호와 토큰도 그대로 사용합니다.

## 검증

서버 테스트 57개를 통과했습니다. 가짜 Notion 응답을 이용하여 필터 쿼리와 페이지 처리, 공동 담당자, 담당자 변경·복원, 타 소스 보존, 전송 직전 재배정, 앱 ID 복구, 사람 목록과 속성 검증, 클라이언트 동기화 병합을 테스트했습니다. PC 화면 검사와 Android 에뮬레이터에서 담당자 선택 → 저장 → 본인 업무만 표시되는 흐름도 확인했습니다. 실제 Notion 계정의 권한과 iPhone 실기기 동작은 연결 후 확인해야 합니다.
